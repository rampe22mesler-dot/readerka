# Readerka: архитектура

Нативный Kotlin/Compose-проект. Минимальная платформа — Android API 28; целевое устройство — Huawei MatePad 11.5 S с HarmonyOS 4.2 и поддержкой APK. INTERNET используется только встроенным окном Google Переводчика; Google Play Services не используются. Совместимость с конкретным планшетом проверяется отдельно от Android-эмулятора.

## PDF

Проверены опубликованные исходники AndroidX PDF `1.0.0-alpha09`: `PdfView` имеет методы выделения и подсветки, но `PdfViewerFragmentV1` требует Android S / SDK Extension 13. Эта комбинация не подходит для заявленного API 28. Официальный сайт developer.android.com недоступен в текущем сетевом профиле, исходники взяты из Google Maven.

Выбраны Android `PdfRenderer` для настоящей отрисовки PDF и открытый PDFBox Android `2.0.27.0` для текстового слоя. `PDFTextStripper` выдаёт Unicode и геометрию `TextPosition`, а не изображение с фиктивными полосками.

`PdfEngine` сериализует доступ к каждой библиотеке отдельной блокировкой: извлечение текста не задерживает отрисовку. PDFBox использует смешанное хранение с ограниченным RAM-буфером (16 MiB) и временными файлами. Страницы отрисовываются по запросу, ширина растра ограничена 2200 px. Растры всего документа одновременно не создаются. LRU изображений ограничен 32 MiB, кэш текста — шестью страницами. Вытесненные bitmap не вызывают recycle, пока AndroidView может их показывать. AndroidView в LazyColumn явно очищается при повторном использовании; назначение bitmap и callbacks происходит в update. Переходы LazyList вынесены из измерения BoxWithConstraints и выполняются после кадра с явным возвратом в Dispatchers.Main. Это исключает измерение AndroidViews на IO-потоке после получения размеров PDF.

Якорь содержит 0-based страницу, диапазон текста и нормализованные прямоугольники относительно отображаемой геометрии PDF-страницы после crop/rotation. Изображение, сохранённая подсветка и текстовые границы используют одну экранную трансформацию. Оригинальный PDF не изменяется. Внешний экспорт всегда преобразует страницу в 1-based номер.

В первой реализации поддерживается текстовое выделение в пределах одной страницы. Для отсканированных страниц без текстового слоя показывается явное ограничение; OCR не выполняется. Извлечение сложного порядка чтения, нестандартных шрифтов и двунаправленного текста требует проверки на реальных документах.

## Данные

Room, версия схемы 2; опубликованная JSON-схема находится в `app/schemas`. Миграция 1 → 2 сохраняет исходные таблицы, добавляет внутренние папки и принадлежности, переносит старые закладки в таблицу с nullable родителем/папкой и положением на странице. Инструментальный тест создаёт реальную базу по сохранённой схеме 1 и открывает её через Room 2. Разрушительное восстановление базы не включено.

- `documents`: название, исходное имя, управляемая копия PDF, метаданные и последняя позиция.
- `document_folders`: независимая иерархия папок библиотеки.
- `entries`: один канонический исследовательский объект; цитата и собственный комментарий хранятся раздельно. Самостоятельная заметка имеет пустую цитату и nullable источник/якорь.
- `collections` + `memberships`: отдельная иерархия заметок и many-to-many принадлежности. Одна цитата в двух папках остаётся одной записью.
- `tags`, `entry_tags`, `document_tags`: нормализованные теги с внешними ключами.
- `bookmarks`: документ, 0-based страница, название, комментарий, нормализованное положение, nullable родительская закладка и внутренняя папка.
- `reader_folders`: вложенные папки одного PDF, раздельные для цитат и закладок.
- `reader_memberships`: принадлежность канонической цитаты папкам внутри её PDF. Не связана с глобальными `collections`.

Изменение комментария, цвета или типа меняет каноническую запись. Удаление принадлежности не удаляет заметку. Удаление папки сохраняет элементы и поднимает её дочерние папки на верхний уровень. Циклы и неизвестные родители отклоняются до записи. Начальная база не содержит тематических папок или демоданных.

DataStore хранит тему, размер текста и цвет по умолчанию. MVVM использует Room Flow / StateFlow. Длительный импорт и экспорт выполняются на IO dispatcher, с индикацией состояния. Жизненный цикл операций связан с ViewModel; WorkManager пока не используется.

## Экспорт и сохранность

`VaultExporter` создаёт новый ZIP. Каждая запись имеет единственный основной Markdown-файл со стабильным ID; в каждой коллекции создаются индекс и ярлыки с `![[...]]`. Папки библиотеки и коллекций независимы, включая пустые папки. Без включённых или доступных PDF сохраняются исходное имя и страница, но ссылки на отсутствующие файлы не создаются.

Внутренние PDF-ссылки используют Obsidian `[[путь.pdf#page=N|название]]`. Автоматические проверки подтверждают структуру ZIP, пути, номера страниц, каноничность и отсутствие ссылок на исключённые PDF. Проверку взаимодействия в настоящем Obsidian нельзя подменять тестом строки: она выполняется отдельно на пользовательском устройстве.

Резервная копия — версионированный JSON и PDF с SHA-256-манифестом. Запись использует формат 2, чтение принимает 1 и 2. ReaderStructure проверяет документ, тип папки и отсутствие циклов у внутренних папок и закладок; восстановление вставляет родителей раньше детей. Obsidian ZIP содержит индексы внутренних папок и иерархию закладок, ссылаясь на канонические цитаты. Восстановление сначала распаковывает архив в staging-каталог, проверяет пути, размеры, контрольные суммы, иерархии и ссылки; только затем выполняет транзакционное добавление. Конфликтующие ID/файлы не перезаписываются. При исключении новая транзакция и созданные ею файлы откатываются. Аварийное выключение процесса между файловой и SQL-операцией может оставить неиспользуемый файл; существующие данные сохраняются.

## Открытые компоненты

- Kotlin и kotlinx: Apache-2.0.
- AndroidX (Compose, Room, DataStore, Lifecycle): Apache-2.0.
- PDFBox Android: Apache-2.0; транзитивный Bouncy Castle — собственная MIT-подобная лицензия.

Версии зависимостей явно закреплены в Gradle. Gradle Wrapper проверяет SHA-256 дистрибутива. TLS и проверки SDK-артефактов не отключаются.

## Управление чтением

ReaderScreen регистрирует обработчик стрелок/Page Up/Page Down/Home/End через Window.Callback и DisposableEffect и снимает его при выходе из чтения; PdfPageView также имеет OnKeyListener. Это сохраняет управление при смене Compose/нативного фокуса. При фокусе на поле редактора обычные стрелки остаются у курсора; при фокусе на PDF они листают страницы. Диалоги имеют собственное окно. Центральное короткое касание без подсветки открывает полосу страниц; короткое касание подсветки открывает редактор с подтверждаемым удалением. TranslationOverlay открывает официальный HTTPS-сайт Google Переводчика в WebView внутри Dialog, без ACTION_VIEW и переключения приложения. Кодированные query-параметры передают выделенный текст, sl=auto и tl=ru; текст также копируется в буфер. INTERNET разрешён для этого окна. JavaScript/DOM storage нужны официальному интерфейсу; доступ к локальным файлам и content URI, mixed content отключены, JavaScript-мост не используется. SSL-ошибки не обходятся. Native PDF canvas пересоздаётся при смене цвета темы, используя уже загруженные bitmap/text; его область отрисовки явно ограничена границами страницы.

## Рабочее пространство 0.3.0

ReaderkaRoot отображает ленту навигации, WorkspaceSidebar с раскрываемым деревом папок и PDF и DocumentTabs. Список открытых ID и активный документ сохраняются в SavedStateHandle; активен один PdfEngine, остальные вкладки открываются по сохранённой позиции Room. Закрытие вкладки освобождает движок, выбирает соседнюю вкладку или возвращает библиотеку, сохраняя сам документ. Ширина рабочей области измеряется без subcomposition; правая структура PDF включается сбоку при доступной ширине от 820 dp. На узких экранах дерево библиотеки показывается поверх содержимого, а полноэкранное чтение скрывает ленту и вкладки.

PageText.wordAt использует Unicode BreakIterator и переводит границы слова в индексы glyph, включая лигатуры. PdfPageView при удержании фиксирует исходное слово; движение в его пределах сохраняет целое слово, движение за пределы расширяет выделение в обе стороны. При перетаскивании уже существующей ручки разрешена точная корректировка до glyph.


## Деревья и фильтры 0.4.0

FolderBrowser — общий LazyColumn для коллекций, внутренних папок PDF, выбора родителей и множественных назначений. FolderTree.visible группирует дочерние папки, сортирует имена и возвращает только раскрытые ветки. Поиск включает найденные папки и цепочки родителей; свёрнутые ветки вне поиска не создают UI-строки. Ветки и строка поиска сохраняются через rememberSaveable. Кнопка + создаёт корневую папку; контекстное меню создаёт подпапку или открывает FolderEditor. Выбор нового родителя исключает папку и её потомков; записи по-прежнему проверяются FolderTree.validate перед транзакцией.

В разделе notes WorkspaceSidebar показывает коллекции; выбранная коллекция хранится в ReaderkaRoot и используется NotesScreen. В библиотеке и чтении панель сохраняет дерево PDF. ReaderPanel использует общий браузер с отдельными деревьями цитат и закладок текущего документа. FolderMembershipChoice хранит предварительный набор флажков до Применить; EntryEditor затем сохраняет memberships и readerMemberships одной существующей транзакцией. Канонические записи не копируются. NoteQuery учитывает потомков выбранной коллекции и возвращает запись один раз при нескольких принадлежностях.

SearchChoice показывает источники/теги в ограниченном LazyColumn с поиском по названию и автору. Пять открытых источников с наибольшим lastOpenedAt располагаются перед остальными; каждый источник присутствует только один раз. Названия обрезаются после двух строк. Миграции базы и новых зависимостей в 0.4.0 нет.


## Черновики, редактор и история 0.5.0

WorkspaceStore использует отдельный Preferences DataStore `workspace_state` с сериализованным WorkspaceState. EntryDraft содержит исходный Entry, свободный текст тегов и оба набора many-to-many назначений. Чтение/сериализация выполняются на Dispatchers.IO. ViewModel держит единственный активный редактор, список закрытых черновиков и ReadingHistory. Conflated Channel объединяет запросы сохранения; Mutex сериализует запись актуального состояния, исключая перезапись новым состоянием из старого запроса. Статус успешного сохранения выставляется только после завершения DataStore и при совпадении текущего состояния с записанным.

DraftEditor управляется состоянием ViewModel; поля больше не ограничиваются remember внутри модального окна. На широком экране редактор заменяет правую панель структуры, оставляя PDF видимым. focusGroup отслеживает фокус всех его полей: обычные стрелки остаются у редактора, когда он имеет фокус; после касания PDF повторные нажатия продолжают перелистывать страницы. На узком экране/в каталоге используется Dialog с теми же полями и обработчиком Ctrl+S / Ctrl+Enter. Закрытие очищает только activeDraftId. При запуске активный редактор и соответствующий источник открываются из дискового состояния. Сохранение сначала завершает прежнюю транзакцию LibraryRepository.saveEntry, затем удаляет черновик из DataStore. Если последняя запись на диск не удалась, редактор остаётся доступен для повторного сохранения; стабильный entry ID предотвращает дубликаты. Удалённые после начала редактирования папки отбрасываются из назначений перед сохранением. Удаление канонической записи также очищает её черновик. Черновики не меняют LibrarySnapshot и формат экспорта/архивов.

ReadingHistory содержит не более 100 ReadingLocation (documentId, 0-based page, нормализованный offset). Переходы по источнику, цитате, закладке/поиску добавляют место; обычное листание обновляет текущую позицию. Новое направление после возврата удаляет ветку вперёд. Индекс истории меняется после успешного открытия движка. Позиция для истории обновляется перед 350-мс debounce записи в Room; первоначальный layout не перезаписывает целевую позицию до выполнения scrollToItem. История хранится в том же DataStore и переживает новый экземпляр ViewModel.

MainActivity устанавливает общий делегирующий Window.Callback, ReaderScreen добавляет свой обработчик чтения. Главное меню команд доступно и вне PDF. QuickCommands открывается как слой внутри Box рабочего пространства, без отдельного системного окна. Это исключает одновременное удаление окна команд и изменение размеров нативного PDF при открытии редактора. Слой блокирует клавиши перелистывания, закрывается по Back/Esc и фильтрует список по словам в названии/описании; показывает не более 100 результатов в LazyColumn и имеет клавиатурный выбор. Переходы выполняют существующие функции открытия, не создавая копий сущностей. ReaderTool в ViewModel доставляет команды поиска/страниц/панелей после перехода к экрану чтения. Новых зависимостей или миграции Room нет.

# Техническое задание для Codex: Android-приложение для чтения PDF и организации академических заметок

## 0. Твоя роль и основная задача

Ты — опытный Android-разработчик и software architect, специализирующийся на Kotlin, Jetpack Compose, PDF rendering и локальных базах данных.

Создай полноценное **нативное Android-приложение, оптимизированное прежде всего для планшетов**, предназначенное для чтения PDF, выделения цитат, написания заметок и организации собственных исследовательских материалов.

Приложение ориентировано на академическую работу, особенно на чтение философской литературы: научных статей, монографий, сборников и книг.

Это не AI-приложение.

**Категорически запрещено встраивать AI, LLM, чат-ботов, автоматическое AI-резюмирование и подобные функции.**

Приложение должно работать локально, без регистрации, серверов и интернет-соединения.

Главный пользовательский сценарий:

1. Я импортирую PDF научной статьи в библиотеку.
2. Открываю PDF и читаю его.
3. Выделяю интересные фрагменты текста разными цветами.
4. К выделению могу добавить собственный комментарий.
5. Могу создавать самостоятельные текстовые заметки.
6. Могу присвоить выделению или заметке тип и теги.
7. После чтения открываю отдельный каталог всех заметок и цитат.
8. Там я могу создавать собственные папки и подпапки, например «Существование», «Онтология», «Возражения Канту».
9. Могу собрать в папке «Существование» цитаты из десяти разных PDF.
10. Могу работать с собранными заметками независимо от исходных PDF: читать, редактировать свои комментарии, менять типы, сортировать, классифицировать и связывать материалы.
11. При необходимости нажимаю на цитату и возвращаюсь к её исходному месту в PDF.

**Главный принцип проекта: мои заметки и цитаты должны существовать как самостоятельная, организуемая база знаний, а не только как комментарии внутри отдельных PDF.**

# 1. Платформа и технологии

Создавай настоящее Android-приложение, а не сайт или WebView-оболочку.

Используй:

- Kotlin;
- Jetpack Compose;
- Material 3;
- Android Architecture Components;
- MVVM;
- Room Database (SQLite);
- Kotlin Coroutines и StateFlow;
- DataStore для настроек;
- Android Storage Access Framework для импорта и экспорта файлов;
- Gradle Kotlin DSL.

Для PDF изучи официальные AndroidX PDF API, включая возможности просмотра, выделения текста, управления позициями и отрисовки цветных выделений.

Не используй Android `PdfRenderer` в одиночку, если выбранное решение не предоставляет корректного извлечения и выделения текста.

Перед выбором библиотеки убедись, что она позволяет реализовать полный сценарий:

**Select text → Get text and position → Save highlight → Display highlight → Reopen exact source.**

В частности, оцени `androidx.pdf` и доступные публичные API для `PdfView`, `TextSelection`, `Highlight` и перехода к позиции в документе.

Проверь совместимость выбранных PDF API с реальными версиями Android и Android SDK Extensions. Не используй функции, которые будут недоступны на заявленных поддерживаемых планшетах.

Предпочтительный минимальный Android SDK — API 28 (Android 9), если выбранный PDF-движок обеспечивает на нём требуемые функции.

Используй совместимые версии зависимостей. Не выдумывай названия библиотек, методов или Gradle-зависимостей.

Не используй React, Electron, Node.js backend, облачную базу данных или сервер.

Приложение должно собираться в устанавливаемый APK.

# 2. Оптимизация для планшетов

Это критически важное требование.

Интерфейс должен проектироваться в первую очередь под Android-планшеты с экранами примерно 8–14 дюймов.

Обязательна поддержка:

- альбомной ориентации;
- портретной ориентации;
- управления пальцами;
- Android-стилуса (например, S Pen);
- экранной клавиатуры;
- внешней клавиатуры и мыши, если подключены;
- многооконного режима Android;
- изменения размера окна.

Используй adaptive layouts и Window Size Classes.

В альбомной ориентации должно быть удобно одновременно видеть PDF и панель заметок.

В портретной ориентации боковые панели могут сворачиваться, чтобы PDF занимал достаточную площадь экрана.

Не растягивай мобильный интерфейс телефона на большой планшет.

Обеспечь достаточно крупные области нажатия для пальца, но при этом не делай чрезмерно большие элементы интерфейса.

Основные действия должны выполняться быстро, без большого количества диалогов.

# 3. Главная навигация

Приложение должно иметь следующие основные разделы:

**Library** — библиотека документов.

**Reader** — чтение PDF.

**Notes & Highlights** — общий каталог цитат, выделений и заметок.

**Collections** — пользовательские папки с заметками и цитатами.

**Settings** — настройки приложения.

Разделы Notes & Highlights и Collections могут быть объединены в одном экране с боковой панелью папок.

Дополнительные функции для исследовательской работы можно добавлять позднее, но не в ущерб главным разделам.

- создавать папки;
- создавать вложенные папки;
- переименовывать папки;

- сортировать документы;

- просматривать недавно открытые документы.

- Philosophy;
- Ethics;
- Metaphysics;
- Epistemology;
- Research;
- Books;
- Other.

Не создавай никаких других тематических папок.

Пользователь должен самостоятельно создавать все папки и определять их структуру.

Системный вид «Все документы» допустим, но он не должен быть пользовательской папкой.

Начальное состояние библиотеки:

**Моя библиотека**

Пока нет документов.

[Добавить PDF] [Создать папку]

## Метаданные документов

Для каждого документа:

- название;
- автор или авторы;
- год;
- журнал или издательство;
- DOI;
- URL;
- произвольное описание;
- пользовательские теги;
- PDF-файл;
- дата добавления;
- дата последнего открытия;
- последняя прочитанная страница.

Не все поля обязательны.

На первом этапе метаданные можно вводить вручную.

Поддержка автоматического извлечения названия из PDF metadata допустима, но не должна создавать сложную систему.

# 5. PDF READER — основная функция

Читалка должна быть качественной и удобной для длительного чтения научной литературы.

Поддержка:

- вертикальной прокрутки PDF;
- перехода между страницами;
- увеличения и уменьшения масштаба;
- pinch-to-zoom;
- fit to width;
- fit to page;
- полноэкранного режима;
- поиска текста в PDF;
- выделения текста пальцем;
- выделения текста стилусом;
- копирования текста;
- закладок;
- цветных выделений;
- комментариев к выделениям;
- боковой панели заметок;
- восстановления последней прочитанной позиции.

## Пример интерфейса на планшете

В альбомной ориентации:

| Левая панель | Основная область | Правая панель |
|---|---|---|
| Содержание | PDF | Заметки |
| Закладки | Страницы документа | Комментарии |
| Выделения | Выделение текста | Цвета |
| Поиск | Чтение | Теги и папки |

Панели должны иметь возможность скрываться.

Главная область чтения должна занимать большую часть доступного пространства.

По умолчанию приложение должно отдавать приоритет чтению, а не показывать одновременно много второстепенных элементов.

# 6. Цветные выделения текста

**Это одна из наиболее важных функций приложения.**

Пользователь должен иметь возможность выделить фрагмент текста в PDF и выбрать цвет подсветки.

Предусмотри удобную цветовую палитру:

- жёлтый;
- зелёный;
- голубой;
- розовый;
- фиолетовый;
- оранжевый.

Цвета должны быть достаточно прозрачными, чтобы текст легко читался.

Цвет выделения должен сохраняться.

Пользователь должен иметь возможность:

- изменить цвет существующего выделения;
- удалить выделение;
- добавить комментарий;
- изменить комментарий;
- добавить тип заметки;
- добавить теги;
- добавить выделение в одну или несколько папок;
- открыть соответствующую запись в глобальном каталоге.

Не связывай жёстко цвета с типами заметок.

Например, пользователь сам решает, что означает жёлтый или зелёный цвет.

В настройках можно позволить выбрать цвет выделения по умолчанию.

## Пример взаимодействия

Пользователь выделяет фрагмент:

"Existence is not a real predicate."

Появляется компактная панель:

🟨 🟩 🟦 🩷 🟪 🟧

Действия:

- Выделить;
- Добавить комментарий;
- Добавить в папку;
- Добавить тег.

Если пользователь выбирает цвет, выделение сразу сохраняется.

Если выбирает «Добавить комментарий», открывается компактный редактор.

**Не заставляй пользователя проходить длинную форму при каждом выделении.**

## Технические требования

Каждое выделение должно сохранять:

- уникальный ID;
- ID исходного документа;
- выделенный текст;
- номер страницы;
- цвет;
- позицию выделения в PDF;
- геометрические координаты фрагментов;
- дату создания;
- дату изменения.

Координаты должны храниться относительно PDF-страницы, а не относительно пикселей экрана.

Учитывай масштаб, прокрутку, поворот и размеры страницы.

Если фрагмент занимает несколько строк, сохраняй соответствующие области текста.

После закрытия и повторного открытия PDF все выделения должны корректно восстанавливаться.

При изменении масштаба выделения не должны смещаться.

Не считай обычную цветную полоску поверх страницы полноценной реализацией выделения, если она не привязана к реальному тексту.

По умолчанию сохраняй подсветку в базе данных приложения, не изменяя оригинальный PDF.

# 7. Комментарии и самостоятельные заметки

Поддержи два способа создания заметок.

## A. Заметка к цитате

Пользователь выделяет предложение:

"Being is not a genus."

После этого добавляет собственный комментарий:

"Нужно выяснить, как это связано с аристотелевским пониманием категорий."

В базе данных должны храниться отдельно:

**Source Quote**

"Being is not a genus."

**My Comment**

"Нужно выяснить, как это связано с аристотелевским пониманием категорий."

Комментарий можно редактировать или удалить, не удаляя цитату.

Одна цитата может иметь основной комментарий и, если архитектура позволяет, дополнительные заметки.

## B. Самостоятельная заметка

Пользователь может создать текстовую заметку без выделения текста.

Например:

Название:

"Проблема существования универсалий"

Текст:

"Нужно сравнить реалистическую позицию с концептуализмом."

У неё может не быть исходного PDF.

Пользователь может:

- редактировать заметку;
- присваивать тип;
- задавать цвет карточки;
- добавлять теги;
- помещать в папки;
- связывать с документами или цитатами.

Обе разновидности заметок должны быть доступны из общего каталога.

# 8. TYPES OF NOTES — типы заметок

Реализуй следующие типы:

| Тип | Назначение |
|---|---|
| Quote | Цитата из источника |
| Summary | Пересказ мысли автора |
| Question | Вопрос |
| Objection | Возражение |
| Agreement | Согласие |
| Idea | Собственная идея |
| Connection | Связь с другой мыслью |
| General Note | Обычная заметка |

Тип должен быть самостоятельным полем данных.

Пользователь может менять тип заметки.

Тип НЕ должен определять, в какой папке находится заметка.

Например:

Цитата:

"Existence is not a predicate."

Type: Quote

Collection: Онтология / Существование

Tags: #Кант #существование

Цвет: жёлтый

Тип, папка, теги и цвет — **четыре независимых свойства**.

По умолчанию можно использовать General Note для самостоятельных заметок и Quote для цитат.

Не создавай автоматически папки с названиями типов.

# 9. NOTES & HIGHLIGHTS — глобальный каталог

**Это второй по важности раздел после PDF-читалки.**

Должна существовать отдельная вкладка, где пользователь работает непосредственно со всеми цитатами и заметками из своей библиотеки.

Она не должна быть просто списком страниц конкретной книги.

В этом разделе должны отображаться:

- выделенные цитаты;
- комментарии к ним;
- самостоятельные заметки;
- информация об источнике;
- тип заметки;
- цвет;
- теги;
- папки.

## Пример карточки

**Цитата**

"Existence is not a real predicate."

*Immanuel Kant — Critique of Pure Reason*

Страница: 214

**Мой комментарий**

"Здесь следует сопоставить аргументацию Канта с онтологическим доказательством."

Тип: Objection

Теги: #Кант #онтология

Папка: Существование

Цвет: жёлтый

Действия:

[Редактировать] [В папку] [Открыть в PDF]

## Возможности каталога

Пользователь должен иметь возможность:

- просматривать все цитаты сразу;
- просматривать все самостоятельные заметки;
- просматривать цитаты вместе с комментариями;
- редактировать собственные комментарии;
- изменять тип заметки;
- изменять цвет;
- назначать теги;
- добавлять записи в папки;
- убирать записи из папок;
- удалять записи;
- сортировать;
- искать;
- открывать PDF-источник.

Важная функция: **множественный выбор**.

Например, пользователь выбирает 15 цитат о существовании и нажимает:

«Добавить в папку» → «Существование».

Все 15 цитат добавляются туда за одну операцию.

Реализуй это обязательно.

# 10. COLLECTIONS — произвольные папки для цитат и заметок

В приложении должны существовать две независимые системы организации:

1. Папки документов в библиотеке.
2. Папки цитат и заметок в каталоге.

Это разные структуры.

## Никаких заранее созданных папок

Не создавай тематические папки автоматически.

Начальное состояние:

**Мои папки заметок**

Пока нет папок.

[Создать папку]

## Пример пользовательской структуры

Пользователь самостоятельно создаёт:

- Онтология
  - Существование
  - Сущность
  - Универсалии
- Эпистемология
  - Истина
  - Знание
  - Скептицизм
- Интересные аргументы
- Вопросы для исследования
- Моя будущая статья

Это только пример. **Не добавляй эти папки в seed data или при первом запуске.**

## Функциональность папок

Нужны:

- создание;
- переименование;
- удаление;
- вложенные папки;
- произвольная глубина вложенности в разумных пределах;
- перемещение папок;
- добавление заметок;
- удаление заметок из папок;
- пакетное добавление нескольких заметок.

**Одна цитата может одновременно находиться в нескольких папках.**

Например:

Цитата из Канта:

"Existence is not a real predicate."

Может находиться одновременно в:

- Онтология / Существование;
- Интересные аргументы;
- Моя будущая статья.

При этом это одна запись базы данных, а не три копии цитаты.

Редактирование комментария должно отражаться во всех папках.

Удаление цитаты из одной папки не должно удалять её из остальных папок или из исходного документа.

Для удаления объекта целиком нужна отдельная команда с подтверждением.

Не путай «Удалить из папки» и «Удалить заметку».

# 11. TAGS — теги

Помимо папок поддерживай теги.

Пользователь самостоятельно создаёт произвольные теги.

Примеры:

#existence  
#ontology  
#kant  
#objection  
#important

Теги могут присваиваться:

- книгам;
- цитатам;
- комментариям;
- самостоятельным заметкам.

Одна запись может иметь несколько тегов.

Теги не заменяют папки.

Например, пользователь может открыть папку «Существование», а внутри отфильтровать цитаты по тегу `#Кант`.

Нужна возможность редактировать и удалять теги.

# 12. Цвета в каталоге

Цвет выделения должен быть виден не только в PDF, но и в общем каталоге.

Например, цитата, выделенная зелёным в PDF, должна иметь зелёный цветовой индикатор в списке.

Пользователь может фильтровать записи по цвету.

Изменение цвета цитаты в каталоге должно автоматически менять её цвет в PDF.

Самостоятельные заметки также могут иметь цветовой маркер.

Цвета не должны определять тематическую классификацию.

---

# 13. SEARCH & FILTERING

В глобальном каталоге должен работать поиск.

Искать можно по:

- тексту цитаты;
- тексту комментария;
- тексту самостоятельной заметки;
- названию источника;
- автору;
- тегам.

Поддержи кириллицу и латиницу.

Фильтры:

- папка;
- источник;
- тип заметки;
- цвет;
- тег;
- дата создания.

Поддержи комбинирование фильтров.

Пример:

Папка: Онтология

Тип: Objection

Цвет: Жёлтый

Результат: все подходящие возражения внутри выбранной папки.

Сортировка:

- новые сначала;
- старые сначала;
- по названию источника;
- по автору;
- по странице источника;
- по типу заметки.

Для поиска по базе при необходимости используй SQLite FTS.

# 15. SOURCE NAVIGATION

Это обязательная функция.

1. Открыть соответствующий PDF.
2. Перейти на нужную страницу.
3. Прокрутить к позиции выделения, если возможно.
4. Показать сохранённое выделение.
5. Дать возможность продолжить чтение.

Не ограничивайся простым открытием первой страницы документа.

Сохраняй исходные якоря выделения достаточно надёжно, чтобы переход работал после перезапуска приложения.

# 16. Работа со стилусом

# 17. Режим чтения и режим работы с заметками

Предусмотри два основных режима.

## Reading Mode

Центральное место занимает PDF.

Панели максимально скрыты.

Пользователь может быстро выделять текст, сохранять цитаты и добавлять комментарии.

## Research Mode

Центральное место занимает каталог заметок.

Пользователь видит собственные папки, цитаты, комментарии и инструменты сортировки.

В этом режиме PDF не обязателен.

Пользователь должен иметь возможность работать с цитатами из нескольких источников, не открывая каждый PDF.

Именно Research Mode отличает это приложение от стандартных Android PDF-ридеров.

# 20. Локальное хранение

Все данные сохраняются локально на Android-планшете.

Используй Room Database.

PDF-файлы импортируй через Android Storage Access Framework.

Для надёжной работы предпочтительно создавать управляемую приложением локальную копию импортированного PDF. Не полагайся только на временный URI выбранного файла.

Не запрашивай разрешение на доступ ко всем файлам устройства без необходимости.

Данные должны сохраняться после:

- закрытия приложения;
- повторного запуска;
- перезагрузки устройства;
- смены ориентации экрана;
- сворачивания приложения;
- перехода между разделами.

PDF не должен повторно импортироваться при каждом запуске.

Для идентификации документов используй устойчивые ID и, при необходимости, хеш содержимого.

Обрабатывай ситуации, когда файл повреждён, зашифрован или не содержит доступного текстового слоя.

Для отсканированных PDF без текстового слоя допускается ограничение: чтение страниц работает, но выделение текста недоступно. Показывай понятное объяснение вместо имитации выделения.

OCR не является обязательной функцией первого MVP.

- комментарии;
- самостоятельные заметки;
- теги;

Эту функцию реализуй после главного цикла чтения и сохранения, но до объявления приложения готовым к повседневному использованию.

# 22.1. ПОЛНЫЙ ЭКСПОРТ В OBSIDIAN (ОБЯЗАТЕЛЬНО)

Реализуй отдельную функцию **«Экспортировать всё в Obsidian»**. Это не экспорт всех цитат в один длинный Markdown-файл, а создание полноценной **структуры папок и отдельных `.md`-заметок**, которую можно открыть как Obsidian Vault без дополнительных плагинов.

## A. Что экспортировать

Экспортируй **все исследовательские данные**, а не только заметки выбранной книги:

- полную иерархию пользовательских папок библиотеки документов;
- полную иерархию пользовательских Collections (папок цитат и заметок), включая вложенность;
- все выделенные цитаты, в том числе без комментариев;
- комментарии к цитатам, отдельно от текста источника;
- самостоятельные заметки, включая не привязанные к PDF;
- типы заметок (Quote, Summary, Question, Objection, Agreement, Idea, Connection, General Note);
- теги, цвета выделений и заметок, даты создания/изменения;
- все принадлежности заметок к коллекциям (в том числе к нескольким одновременно);
- информацию о каждом PDF: **исходное имя PDF-файла с расширением `.pdf`**, название документа, авторов и доступные метаданные;
- **точную страницу PDF**, на которой находится цитата; номер экспортируемой страницы должен быть 1-based (первая страница PDF = 1), независимо от внутренней 0-based индексации PDF-библиотеки;
- закладки с документом, страницей, названием и комментарием;
- существующие связи между заметками, если функциональность Relationships уже реализована.

Если у PDF есть печатная пагинация, отличная от номера страницы PDF, можно дополнительно сохранять `printed_page_label`, но **никогда не заменять ею фактическую страницу PDF**.

## B. Структура экспортируемого Obsidian Vault

Создай ZIP-архив с папкой для нового Obsidian Vault. Используй, например, такую структуру (это пример пользовательских папок, а НЕ предустановленные папки в самом приложении):

```text
My Research Vault/
├── Библиотека/
│   └── Онтология/
│       └── Kant_1781.pdf
├── Источники/
│   └── Kant — Critique of Pure Reason.md
├── Заметки/
│   ├── Цитаты/
│   │   └── Existence is not a predicate — hl_00271.md
│   └── Самостоятельные/
│       └── Проблема универсалий — n_00115.md
├── Коллекции/
│   ├── Онтология/
│   │   ├── _Коллекция.md
│   │   └── Существование/
│   │       ├── _Коллекция.md
│   │       └── Existence — ссылка — hl_00271.md
│   └── Идеи для статьи/
│       └── _Коллекция.md
├── Закладки/
│   └── Kant — страница 214 — bm_0003.md
└── _Содержание.md
```

Ветка `Библиотека/` должна воспроизводить **реальную, пользовательскую иерархию папок документов**, а ветка `Коллекции/` — **реальную, независимую иерархию папок заметок**. Ничего не группируй по произвольно назначенным Codex философским темам. Пустые пользовательские папки тоже сохраняй.

Для работы ссылок внутри Obsidian предоставь опцию **«Включить исходные PDF»** (по умолчанию включена). При её включении копируй PDF в архив в соответствующие папки библиотеки. Если опция выключена, всё равно сохраняй исходное имя файла, страницу и другие сведения об источнике; не создавай заведомо нерабочих ссылок на отсутствующие PDF.

## C. Каждая цитата и заметка — отдельный Markdown-файл

Создай для каждой цитаты и самостоятельной заметки отдельный `.md`-файл с устойчивым уникальным ID. Названия файлов должны быть читаемыми, но при совпадениях не перезаписывать друг друга. Используй безопасные имена файлов и стабильный суффикс-ID.

В начале файла используй корректный Obsidian-совместимый YAML frontmatter (Properties). Например:

```markdown
---
id: hl_00271
type: Objection
source_pdf: "Kant_1781.pdf"
source_page: 214
source_title: "Critique of Pure Reason"
source_pdf_path: "Библиотека/Онтология/Kant_1781.pdf"
color: yellow
tags:
  - Кант
  - существование
collections:
  - Онтология/Существование
  - Идеи для статьи
created_at: "2026-10-08T12:00:00"
---
# Existence is not a real predicate

## Цитата
> Existence is not a real predicate.

## Мой комментарий
Здесь Кант возражает против онтологического доказательства.

## Источник
- PDF-файл: `Kant_1781.pdf`
- Страница PDF: **214**
- Открыть источник: [[Библиотека/Онтология/Kant_1781.pdf#page=214|Kant_1781.pdf — страница 214]]
```

Синтаксис перехода к странице PDF через ссылку Obsidian **проверь на реальном Vault**. Если выбранный вариант ссылки в актуальном Obsidian не работает, реализуй другой подтверждённо работающий способ; неизменяемые поля `source_pdf` и `source_page` должны сохраняться независимо от ссылки.

Исходная цитата и комментарий пользователя всегда должны оставаться в разных разделах. Самостоятельная заметка без PDF не должна получать выдуманное имя источника или номер страницы.

Дополнительно экспортируй метаданные документа в `Источники/` и предоставь из цитаты Markdown-ссылку на соответствующую карточку источника.

## D. Одна заметка в нескольких коллекциях — без дублирования

Одна цитата может принадлежать сразу нескольким коллекциям. Не создавай несколько независимых копий одного и того же содержимого, поскольку они разойдутся при последующем редактировании.

Используй следующую структуру:

- **Единственный основной `.md`-файл заметки** в `Заметки/`;
- у каждой пользовательской коллекции — своя папка в `Коллекции/` и файл `_Коллекция.md`;
- в `_Коллекция.md` размещай список Obsidian wiki-links `[[...]]` на основные файлы всех заметок, принадлежащих этой коллекции;
- в YAML каждой заметки сохраняй полный список путей её коллекций;
- **в каждой папке коллекции обязательно создай Markdown-файлы-ярлыки** для входящих в неё цитат и заметок, содержащие ссылку на канонический файл и его Obsidian-встраивание `![[Заметки/Цитаты/...]]`; благодаря этому записи видны прямо в дереве файлов Obsidian;
- такие ярлыки не должны копировать содержимое заметки и не должны становиться отдельной редактируемой версией её текста.

Таким образом, структура папок и членство заметок сохраняются, ссылки работают, а у каждой цитаты остаётся одна основная версия. Укажи в `_Содержание.md`, как устроены эти коллекции.

## E. Дополнительные требования

- Экспорт должен работать **полностью офлайн**.
- Используй Android Storage Access Framework: пользователь выбирает, куда сохранить ZIP, либо выбирает папку для экспорта, если это надёжно поддерживается.
- Не изменяй оригинальные PDF, заметки и базу данных во время экспорта.
- Экранируй специальные символы Markdown/YAML, Unicode и символы путей; учитывай кириллицу, кавычки и одинаковые названия файлов.
- Генерируй все Obsidian-ссылки относительно экспортируемого Vault; не используй абсолютные пути с Android-планшета.
- Создай `_Содержание.md` с индексом коллекций и источников.
- При повторном экспорте обеспечь устойчивость имён файлов и ID. По умолчанию создавай новый архив/снимок, **не перезаписывай пользовательские правки в существующем Obsidian Vault**.
- Экспорт в Obsidian — **односторонний перенос данных**, не заявляй синхронизацию или обратный импорт, пока они не реализованы.
- Большие объёмы данных экспортируй в фоне, с индикатором прогресса и корректной обработкой ошибок.
- Если часть PDF недоступна, явно сообщи об этом в отчёте экспорта, но сохрани связанные заметки и сведения об источнике.

## F. Приёмочный тест Obsidian Export

1. Создать в приложении вложенные папки библиотеки и коллекций.
2. Импортировать два PDF с отличающимися именами файлов.
3. Сделать цитаты на разных страницах и добавить комментарии разных типов и цветов.
4. Создать самостоятельную заметку и одну цитату поместить одновременно в две коллекции.
5. Выполнить «Экспортировать всё в Obsidian» с включёнными PDF.
6. Распаковать ZIP и открыть папку как Obsidian Vault.
7. Проверить сохранение дерева пользовательских папок и коллекций, всех цитат, заметок, тегов и цветов.
8. Проверить, что у каждой цитаты указаны **точное исходное имя PDF с расширением `.pdf` и номер страницы PDF**.
9. Проверить, что ссылки на заметки и на PDF работают, и переход к указанной странице открывает корректную страницу.
10. Проверить, что цитата, включённая в две коллекции, ведёт к одному основному Markdown-файлу, без дублирования содержимого.
11. Проверить, что экспорт без копирования PDF по-прежнему сохраняет имена источников и страницы.
12. Убедиться, что экспорт не изменил исходную библиотеку приложения.

# 25. PERFORMANCE

Приложение должно хорошо работать на обычном Android-планшете, а не только на мощном флагманском устройстве.

Особенно важно:

- плавное перелистывание PDF;

# 26. КРИТИЧЕСКИЙ ТЕХНИЧЕСКИЙ ПРОТОТИП

**Прежде чем создавать все экраны приложения, реализуй и проверь прототип самого сложного сценария: PDF text selection and highlight persistence.**

Проверочный сценарий:

1. Открыть настоящий PDF с текстовым слоем.
2. Выделить предложение пальцем.
3. Получить точный текст выделения.
4. Получить устойчивую привязку к PDF.
5. Выбрать жёлтый цвет.
6. Сохранить данные в Room.
7. Закрыть приложение.
8. Снова открыть PDF.
9. Убедиться, что выделение осталось на нужном тексте.
10. Изменить масштаб.
11. Убедиться, что подсветка не сместилась.

13. Убедиться, что изменение сохранилось.
14. Открыть запись из глобального каталога.
15. Перейти точно к исходному месту в PDF.

Повтори тест на многострочном выделении и на PDF с другой геометрией страницы.

Если выбранная PDF-библиотека не даёт достаточного контроля над выделениями, найди технически подходящую альтернативу и объясни выбор.

Не продолжай разработку основного интерфейса, опираясь на непроверенный PDF-движок.

# 32. Главный принцип разработки

**Приложение предназначено не столько для хранения PDF, сколько для превращения прочитанной литературы в собственную, организованную систему цитат, комментариев и идей.**

PDF — это исходный материал.

Цитаты и заметки — это самостоятельные исследовательские объекты.

Папки, теги, цвета и типы заметок — это инструменты организации этих объектов.

В приоритете:

1. Удобное чтение на Android-планшете.
2. Надёжные цветные выделения.
3. Быстрые комментарии.
4. Самостоятельный каталог цитат и заметок.
5. Свободная организация материалов в пользовательские папки.
6. Сохранность данных.
7. Производительность и удобство использования.

Начни с создания нативного Android-проекта и проверки PDF annotation workflow, затем последовательно реализуй MVP.

Главный критерий успеха:

Я могу прочитать несколько десятков философских PDF, собрать сотни цитат, разложить их по самостоятельно созданным тематическим папкам и продолжить работать с ними как с собственной исследовательской библиотекой — не открывая каждый исходный документ отдельно.

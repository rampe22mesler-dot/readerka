# Android-порт Readerka: аудит и приёмка

Подготовлена проверочная Android 1.0.0 на общей модели текущего desktop. Основные проверки данных и отдельные GUI сценарии прошли; полный набор 53 и физический Huawei пока не подтверждены.

Исходный checkout: 5e750f8, Windows 1.0.0, Android 0.9.0 / Preview 0.9.0. Рабочая ветка `work`. Пользователь уточнил: новая Android-версия ориентируется на desktop; исходники Windows не изменяем. Исходный Android: minSdk 28, compile/target 35, AGP 8.9.1, Kotlin 2.1.20, PDFBox Android 2.0.27.0, Room 4, ZIP 4. Windows: JVM 17, ZIP 5, SQLite/JDBC JSON-состояние. Google Play Services/HMS не используются.

## Решения перед реализацией

- Развиваем существующий `app/`; `windows/shared` подключается в Android Gradle-корень как `:shared`. Удаляются расходящиеся копии моделей/операций и экспортёров. Swing, AWT и JDBC остаются только в desktop.
- Room сохраняется. Явная миграция 4→5 добавляет таблицу полей и квитанции файловых транзакций, существующие записи не пересоздаются. Номера Room и ZIP независимы.
- Android PdfRenderer (рендер) и PDFBox Android (текст/геометрия) остаются. На API 28 не используются методы текста PdfRenderer из API 35. Якоря из архива не пересчитываются.
- EditText внутри Compose сохраняется для IME. Форматирование работает через общий RichText с UTF-16 диапазонами и стабильными ID блоков.
- Обмен использует общие ZIP 5/LibraryMerge, проверку перед записью, резервную копию и файловый журнал, связанный с транзакционной квитанцией Room.
- Android-адаптеры файлового журнала/графа находятся в `app/`; HTTP/PKCE-клиент генерируется из неизменённого desktop-протокола с адаптером потоков API 28.
- Для phone показывается активная область, вторая сохраняет вкладки. Две области включаются только при достаточной доступной ширине, включая IME.
- ApplicationId обоих вариантов сохраняется. Проверочный debug APK не доказывает совместимость подписи с установленным приложением. Релизный ключ не извлекается и не заменяется.

## Уровни подтверждения

Пользователь подтвердил HarmonyOS 4.2; физический Huawei не доступен. Установленный на планшете API и совместимость подписи пока не подтверждены. `/dev/kvm` в облачной машине отсутствует; используется программный эмулятор AOSP API 28 и дополнительный API 30. Windows MSI/EXE на Linux не проверяется. Настольная база до изменений: 68 shared pass; desktop с дисплеем 68 pass, 1 skip, 3 fail (две Windows-only DjVu, QuoteEditingUiTest высота поля). Все данные проверки синтетические.

## Проверки итоговой сборки

- Оба debug APK собраны: `org.readerka` / `org.readerka.preview`, versionCode 10, minSdk 28, targetSdk 35; arm64-v8a и x86_64. Подписи проверены, DEX, нативные библиотеки и шрифты двух вариантов совпадают. SHA-256 и сертификат: `APK-METADATA.json` / `APK-SHA256SUMS.txt` в каталоге артефактов.
- 49 Android unit-тестов и 68 тестов неизменённого shared прошли, без пропусков. Lint: 0 errors, 42 warnings.
- API 28 x86_64 без GMS: 9 существующих проверок миграций/PDF/черновиков и 8 новых проверок ZIP 5, политик, файлового журнала и импорта прошли, без пропусков. Нативные DjVu OCR/поворот и многостраничный TIFF проверены на x86_64; ARM64 только собран.
- Обратный ZIP Android→desktop проверен неизменёнными настольными классами: ID, marks, block IDs, поля/группы/комментарии/направления связей, порядок/геометрия, SHA-256 PDF и новая цитата на повёрнутой странице. Проверено визуальное попадание минимум 80% прямоугольников текста.
- API 30: поля/граф, undo/сборка, Activity recreation, защита от восстановления удалённой записи отложенной правкой, каталог touch/key/mouse, папки и несколько принадлежностей прошли в отдельных завершённых группах.
- Вкладки, переключение/позиции страниц, закрытие и Activity recreation прошли в отдельном завершённом повторении (`api30-final-desktop-tabs.xml`, 1 pass, 0 fail/skip). Последняя вкладка оставляет пустую область; видимая команда «Открыть PDF» возвращает библиотеку, как проверено по desktop.
- Источники конспекта и вставка из библиотеки прошли автоматически на итоговом APK.
- Создание цитаты через реальное выделение PDF, открытие источника и Activity recreation прошли. Клавиатурные Ctrl+S/Ctrl+Enter прошли после исправления фокуса/отправки через окно. Новый ViewModel восстановил PDF-страницу, выделение, масштаб и смещение без лишней цитаты.
- Группа IME завершилась: 2 pass, 0 fail/skip, complete=true. Первый сценарий проверил длинный текст, курсор/сохранение над реально видимой IME и имеет подтверждающий снимок. Во втором снимке клавиатура уже скрылась: прежний проход недостаточен для подтверждения сохранения над IME. Тест усилен повторным касанием редактора и обязательной проверкой IME > 100 px после ввода, до проверки Save/снимка; усиленное повторение завершилось: 1 pass, 0 fail/skip, complete=true (`api30-final-ime-visible.xml`). Новый снимок показывает видимую клавиатуру и сохранение над ней. Оба IME сценария подтверждены отдельно; исходный менее строгий проход сохранён как `api30-final-ime-original`.
- На новом редакторе автоматически прошли независимый Unicode undo/IME composition цитаты и комментария с сохранением форматирования/ID блоков, а также размеры 320/360 dp с fontScale 1.3, видимым сохранением и сохранением обоих черновиков.
- Клавиатурное рабочее пространство, закрытие общей правки только в активной области и перетаскивание принадлежности мышью без копирования канонической записи прошли. Исправленный сценарий рабочего пространства с касаниями прошёл на итоговом APK без ручного вмешательства.

## Исправления, найденные при приёмке

Восстановление рабочего пространства завершает старт до открытия команд и deep links. Активное выделение PDF защищено от повторного восстановления сохранённого выделения; счётчик страниц закреплён, палитра доступна отдельной строкой, выбранная вкладка прокручивается в видимую область. Запрошенная PDF-страница/смещение сохраняются сразу и ограничиваются после загрузки движка.

Native EditText обновляет шрифт/цвет/spans только при изменениях; fontScale применяется один раз. Статус ручного сохранения конспекта устанавливается после сохранения рабочего пространства, только если текст соответствует сохранённому снимку. Тестовые предусловия задают scope папок, независимые ID вкладок, исходный layout и реальный фокус редактора; текст и принадлежности проверяются в сохранённом состоянии.

Реальные снимки итогового приложения: `screenshots/readerka-workspace-light.png`, `screenshots/readerka-workspace-dark.png`, а также поле, граф, конспект и папки в той же папке. Это синтетические данные; снимки не заменяют результаты тестов.

Повторение вкладок на итоговом APK проверило страницы/переключение/закрытие второй вкладки и Activity recreation, затем упало на прежнем ожидании автоматического перехода в библиотеку после последней вкладки. Неизменённый desktop (`DesktopWindow.closeTab/collapseIfEmpty`) оставляет пустую область. Тест обновлён: требует отсутствия вкладок/reader, видимой команды «Открыть PDF» и перехода в библиотеку по этой команде; проверка закрытия не удалена. Повторение прошло полностью: 1 pass, 0 fail/skip, complete=true.
